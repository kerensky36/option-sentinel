# Implementation Plan: Option Payoff Graphs

**Branch**: `015-payoff-graphs` | **Date**: 2026-05-23 | **Spec**: [spec.md](spec.md)

## Summary

Add inline payoff-at-expiration charts to the positions table. Clicking a spread group row (or a standalone option row) toggles an SVG payoff diagram injected as a `<tr>` directly below the row. The chart shows the combined net P&L curve, max gain/loss annotations, per-leg strike markers, and a zero line — all rendered in pure SVG with no external library, matching the app's dark monospace theme. Two new client-side JS modules are added (`payoff_math.js`, `payoff_graph.js`); `positions_ui.js` is extended to wire the click handler. Python unit tests validate the payoff arithmetic before JS implementation begins (TDD).

## Technical Context

**Language/Version**: JavaScript ES Modules (browser-native); Python 3.11 for tests
**Primary Dependencies**: None new — pure SVG rendered via DOM string injection; existing Tailwind CSS
**Storage**: None — graph computed on-the-fly from position data already in memory; no new sessionStorage keys
**Testing**: pytest (Python unit tests for payoff math formulas); browser manual verification via quickstart.md
**Target Platform**: Chrome/Firefox/Safari — same as rest of app
**Project Type**: Frontend feature only — no backend changes
**Performance Goals**: Graph renders synchronously in < 100ms; SVG generation is pure arithmetic with 200 data points
**Constraints**: No external chart libraries; no CDN URLs; no eval(); CSP-safe (no script tags injected); dark theme required
**Scale/Scope**: Client-side only; operates on existing in-memory position data

## Implementation Notes

### Payoff Math Module (`payoff_math.js`)

Pure ES module, zero imports. Exports three functions:

```js
// leg = { strike: number, optionType: 'call'|'put', quantity: number, cost: number }
export function legPayoffPerShare(leg, price) { ... }
export function combinedPayoff(legs, price) { ... }
export function analyzePayoff(legs) { ... }  // returns PayoffAnalysis
```

Position data normalisation (done in payoff_graph.js, not payoff_math.js):
```js
// Convert PositionView fields to PayoffLeg:
const leg = {
  strike:     parseFloat(pos.strike),
  optionType: pos.option_type,
  quantity:   pos.quantity,
  cost:       parseFloat(pos.cost),
};
```

### SVG Graph (`payoff_graph.js`)

Imports from `payoff_math.js`. Renders into a fixed `viewBox="0 0 800 180"` with CSS `width: 100%` for responsiveness.

Colour palette (all from existing Tailwind/app palette):
- Zero line stroke: `#4b5563` (gray-600), dashed
- Strike lines: `#6b7280` (gray-500), dashed, labelled
- Payoff curve: `#e5e7eb` (gray-200), single polyline
- Max gain text/tick: `#4ade80` (green-400)
- Max loss text/tick: `#f87171` (red-400)
- Axis lines: `#374151` (gray-700)
- Label text: `#9ca3af` (gray-400), font-family: "JetBrains Mono", monospace, 10px

Graph row HTML inserted after target row:
```html
<tr class="payoff-graph-row" id="payoff-{id}">
  <td colspan="15" class="px-4 py-3 bg-gray-900/60">
    {SVG string}
  </td>
</tr>
```

### Click Wiring (`positions_ui.js` modification)

After `container.innerHTML = ...` in `renderPositions()`:

```js
import { initPayoffGraphToggle } from './payoff_graph.js';
// ... (after innerHTML assignment)
initPayoffGraphToggle(container);
```

`initPayoffGraphToggle(container)` reads all `[data-spread-id]` and `[data-position-id]` rows from the rendered table and adds delegated click handlers. It also adds a global Escape key listener (removed on next render).

For standalone rows, `positions_ui.js` must add `data-position-id` attribute and an `escapeHtml`-safe label attribute (underlying + expiry) to the `<tr>` so the graph module can form a title without re-parsing.

### Standalone Row Attribution

Modify `renderLegRow` in `positions_ui.js`:
```html
<tr ... data-position-id="${escapeHtml(p.symbol)}"
         data-pos-underlying="${escapeHtml(p.underlying_symbol)}"
         data-pos-expiry="${escapeHtml(p.expiry_date)}">
```

The graph module reads these attributes (not inner text) to avoid any DOM-parsing XSS risk.

### Graph Module State

```js
let openGraphId = null;  // tracks currently open graph row id
```

The module does NOT track which `container` is active — `initPayoffGraphToggle` is called fresh on each `renderPositions` invocation (because `innerHTML` replaces everything), so stale listeners are automatically garbage collected.
