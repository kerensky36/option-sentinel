## Summary

Deploy Option Sentinel to GCP using Cloud Run for the stateless FastAPI backend and Firebase Hosting for the pre-rendered static frontend. Firebase Hosting serves static HTML/JS/CSS from CDN and proxies `/api/**` and `/auth/**` requests to Cloud Run. A Python build script pre-renders the existing Jinja2 templates to static HTML. Three shell deploy scripts (backend, frontend, combined) let the operator deploy from a clean checkout with one command.

---

## Technical Context

**Language/Version**: Python 3.11+ (backend, build script), Bash (deploy scripts), Vanilla JS (frontend — unchanged)
**Primary Dependencies**: FastAPI + uvicorn (Cloud Run container), Jinja2 (build script pre-render), gcloud CLI (backend deploy), firebase-tools CLI (frontend deploy)
**Storage**: None server-side. `dist/` is a generated build artefact (gitignored).
**Testing**: Manual smoke tests per quickstart.md; `pytest tests/` continues to cover backend logic
**Target Platform**: GCP Cloud Run (Linux container, us-central1), Firebase Hosting CDN (us-central1)
**Project Type**: Deployment infrastructure for existing stateless web service
**Performance Goals**: Cold start < 3 s; HTML page loads from CDN < 500 ms; full deploy < 10 min
**Constraints**: `max-instances=1` (in-memory PKCE state); `min-instances=0` (scale-to-zero); no DB, no volume mounts; Firebase proxy forwards cookies named `__session` only (not applicable — this app uses no server-side session cookies)
**Scale/Scope**: Single operator, single GCP project, single Cloud Run instance, one Firebase Hosting site

## Phase Design

### Phase 1: Bug Fix — Remove Dead `setup_required` Check

Remove the `SCHWAB_CC_ACCOUNT_ID` guard from the screener route (leftover from before T051 removed the env var dependency from the screener service). Without this fix, the screener page would always show "Setup Required" in production.

**File**: `src/api/routes/screener.py`
**Change**: Delete `setup_required = not bool(os.environ.get("SCHWAB_CC_ACCOUNT_ID"))`. Remove the `setup_required` key from the `TemplateResponse` context (or pass `"setup_required": False` explicitly). Remove the `{% if setup_required %}` block from `screener.html` entirely — it is dead code in the stateless architecture.

---

### Phase 2: Frontend Build Script

Create `scripts/build_frontend.py`:
- Uses `jinja2.Environment(loader=FileSystemLoader("frontend/templates"))` — loader must be rooted at the directory containing `base.html`
- Renders `dashboard.html` → `dist/index.html` with `{"current_page": "thesis_monitor"}`
- Renders `screener.html` → `dist/screener/index.html` with `{"current_page": "covered_call_screener", "setup_required": False}`
- Copies `frontend/static/` → `dist/static/` using `shutil.copytree`
- Cleans `dist/` before building (to avoid stale files)

---

### Phase 3: Firebase Configuration

Create `firebase.json` with:
- `"public": "dist"` — pre-built static files
- `"cleanUrls": true` — `/screener` serves `screener/index.html`
- `"trailingSlash": false`
- Cache-Control headers for `/static/**` (1 year, immutable)
- Rewrites: `/api/**` and `/auth/**` → Cloud Run service; `**` → `/index.html`

Create `.firebaserc` with `{"projects": {"default": "<placeholder>"}}`. Operator replaces `<placeholder>` with GCP project ID during setup, or the frontend deploy script writes it dynamically from `GCP_PROJECT_ID`.

Add `dist/` to `.gitignore`.

---

### Phase 4: Deploy Scripts

Create `scripts/deploy_backend.sh`:
- Validates: `GCP_PROJECT_ID`, `SCHWAB_CLIENT_ID`, `SCHWAB_CLIENT_SECRET`, `SCHWAB_REDIRECT_URI`, `SCHWAB_AUTH_URL`, `SCHWAB_TOKEN_URL`
- Runs: `gcloud run deploy $CLOUD_RUN_SERVICE --source . --region $CLOUD_RUN_REGION --platform managed --min-instances 0 --max-instances 1 --allow-unauthenticated --set-env-vars "SCHWAB_CLIENT_ID=...,..." --project $GCP_PROJECT_ID`
- Captures and prints the service URL from `gcloud run services describe` output

Create `scripts/deploy_frontend.sh`:
- Validates: `GCP_PROJECT_ID`, `CLOUD_RUN_SERVICE_URL`
- Writes `.firebaserc` with `GCP_PROJECT_ID`
- Runs `python scripts/build_frontend.py`
- Runs `firebase deploy --only hosting --project $FIREBASE_PROJECT`
- Prints the Firebase Hosting URL

Create `scripts/deploy.sh`:
- Sources `deploy_backend.sh`, captures Cloud Run URL
- Exports `CLOUD_RUN_SERVICE_URL`, calls `deploy_frontend.sh`
- Prints both URLs; exits non-zero if either fails

---

Update the "Cloud Run Deployment" section in `README.md` to reference `scripts/deploy.sh` instead of raw `gcloud run deploy` commands with the old env var names.
